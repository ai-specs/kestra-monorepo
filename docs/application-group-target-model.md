## 应用组和应用

“应用组”是原“应用项目”的新用户术语。它表示应用、scope 标识和应用组内用户 scope 授予关系的组织范围，避免与业务项目或开发工程混淆。

应用是接入应用组的具体系统。应用通过 OIDC 接入，是应用组成员。当前 Kestra 应用属于第一个内置应用组的普通应用成员，没有额外的身份类别。

第一个应用组是内置应用组，不允许删除。应用组列表使用卡片入口；点击卡片进入只读详情，用户主动点击编辑后才进入编辑状态。查看和修改权限分别检查。

## Scope

应用组声明 scope 标识。scope 在应用组内承担 RBAC 角色标识的作用，不包含应用组级资源和动作权限。

scope 具有三个字段：`key` 是简短英文稳定标识，`name` 是人类可读的 RBAC 角色名称，`description` 是角色用途说明。`key` 创建后不可修改或改名；应用组可以新增 scope，只有所有应用均登记不再使用时才允许删除。

## 用户、应用和权限

应用组内的用户与 scope 绑定，决定用户获授哪些 scope。scope 相当于 RBAC 模型中的角色。

应用接入应用组时，主动声明或登记支持哪些 scope，并为 scope 登记应用权限元数据。登记是应用内部实现的镜像，用于表示支持范围和在 OAuth2 授权页展示，不是应用运行时权限的事实来源；它可能与应用代码不同步。

应用权限登记至少包含独立的权限 `key` 和人类可读的权限 `name`。scope `key/name` 与应用权限 `key/name` 是两组不同字段。

```text
该应用可授权的 scope 范围 = 该应用主动声明或登记支持的 scope 集合
用户在该应用可获得的 scope 上限 = 应用可授权的 scope 范围 ∩ 应用组授予该用户的 scope
```

## OIDC

当前方案使用真正单一的 issuer 和共享的 OIDC discovery、authorization、token 等端点。应用组区分使用经过签名并验证的应用组 claim，不修改 `iss` 编码应用组，也不放宽标准 issuer 校验。

多应用组、多 issuer 延期到当前完整功能由用户验收后再单独立项。本轮不得增加多 issuer 路由、发现端点、配置入口或兼容分支。

## 页面职责

- 概览：查看应用组基本信息和入口，不展示应用组级授权配置状态。
- scope：管理应用组声明的 scope `key`、`name`、描述和受限删除。
- 应用：管理应用接入登记，展示应用支持的 scope 范围，以及 scope 与应用权限元数据的增删改查关系。
- 用户授权：管理应用组内用户与 scope 的绑定。

不存在“身份目录”“本地权限”“应用组级 scope 配置状态”或“完整应用组恢复”这些目标概念。应用权限必须在具体应用上下文中说明。

## 尚未裁决的实施决定

以下事项必须由维护者裁决后才能实施。未决期间，对应工作块不得开工，实施方不得自行选定：

1. **"应用组"的英文目标标识。** 全栈改名覆盖 API 路径、请求与响应字段、数据库表及字段、配置项、claim 名称和代码标识，需要目标英文词（候选如 `group`、`app-group`、`application-group`）。该词未定前，改名工作块无法启动。
2. **当前应用（Kestra）运行时权限的事实来源。** 登记元数据不是运行时权限的事实来源已定；当前应用的事实来源（插件数据库策略是否作为 Kestra 应用内部实现的载体保留、由谁管理）未定。优化文档 §2.2 与 §2.12 对"插件保存的授权内容"的定义须显式协调。
3. **范围外 scope 请求的处理。** 授权请求包含应用可授权范围之外的 scope 时，整体拒绝还是收窄签发，须裁决；并须与"已知但未配置应用权限的 scope 混入 token 时整体拒绝"（优化文档 §5）的关系一并澄清。
4. **替换文案、内置识别与键去向。** 含优化文档 §4.1–4.4 替换文案、§4.5 内置应用组识别规则（含第一方 client 成员记录可被删除的边界）、§4.6 第一方标记 A 或 B、reconciliation 相关翻译键的逐键去向，以及 scope `name` 与 `description` 可否独立修改、`key` 字符集与最大长度、`name` 重复与多语言规则（优化文档 §2.11）。

## 验收

- 应用组卡片、只读详情和显式编辑通过真实浏览器。
- scope key/name/description 和受限删除通过 UI、REST 和存储检查。
- 应用支持 scope 登记与应用权限元数据 CRUD 通过真实应用上下文检查。
- 用户 scope 授予与应用支持范围交集通过真实登录、REST、MCP 检查。
- 同 scope 授权完整，禁止跨 scope 拼接；拒绝操作核对数据库、队列和存储无副作用。
- 单一 issuer、签名应用组 claim、issuer/audience/project/client 边界和撤权通过安全验收。
