# 扩展功能集清单

本文件是 `kestra-monorepo` 的跨仓扩展目录。它适用于当前扩展和未来新增的
`kestra-plugin-*` 项目，不把当前唯一已接入的 RBAC 扩展当作通用业务模板。

## 当前清单

| 扩展功能集 | 仓库 | 接入通道 | 当前状态 | 详细说明 |
|---|---|---|---|---|
| RBAC / 应用组授权 | `kestra-plugin-rbac` | classpath jar、宿主管理 UI SDK | 已接入并通过当前正式组合验收 | [插件 README](../kestra-plugin-rbac/README.md)、[应用组模型](../kestra-plugin-rbac/docs/application-groups.md) |

当前没有其他已发布扩展功能集。未来项目必须在独立仓完成自身 CI、正式产物和公开
契约后，才可以加入“已接入”状态；候选项目应标为“候选”或“调查中”，不得写成
可部署能力。

## 扩展接入边界

- `kestra-overlay` 提供 Kestra 宿主、公开 SPI、UI SDK、扩展激活点和镜像承载能力。
  它不实现扩展业务模型、业务存储或扩展专属授权。
- `kestra-monorepo` 负责 Compose、正式镜像与扩展产物选择、部署配置和跨仓组合验收。
  它不替代扩展仓的业务测试和独立发布。
- 每个 `kestra-plugin-*` 仓负责自己的业务模型、API、页面、存储、权限、迁移、
  配置和生命周期说明，并且只消费已发布宿主产物。

## 新增清单项

新增扩展功能集时，必须提供以下信息：

1. 独立仓名称、扩展功能集名称和业务边界。
2. 宿主版本、公开 SPI 或 SDK 版本、接入通道和约定产物文件名。
3. 正式 CI run、artifact 或镜像 digest、provenance 和 SHA-256。
4. 配置、首次启用、停用、升级、迁移、卸载和失败关闭行为。
5. 独立仓的业务、安全和适用 UI 验收入口，以及根仓组合验收入口。

若宿主机制不足，先在 `kestra-overlay/docs/` 的现有能力文档中记录扩展点提案，
经宿主测试和扩展组合验收后，再把该项目加入本清单。不得通过在 README 中增加一行
名称，替代公开契约、正式发布或组合验收。
